1 — Stop Repeating Code With Your First Dependency

Picture ten routes that all read the same two settings. A dependency is a plain function FastAPI calls for you before your route runs. You write that setup once, instead of in every route. Without one, each route copies the same parameter list, and a later fix has to land in every copy.

You hand a dependency to FastAPI with Depends(), used as a parameter's default value. FastAPI calls the function first, then passes its return value into your route under that parameter's name.

Without a dependency → with oneCopy skip/limit into every route  → Write common_params() once
Fix a bug in ten places           → Fix it in one function
Guess which routes still match    → Every route calls the same code
Wrong — the same two parameters, copied
@app.get("/items")
def list_items(skip: int = 0, limit: int = 10):
    return ITEMS[skip:skip + limit]

@app.get("/users")
def list_users(skip: int = 0, limit: int = 10):
    return USERS[skip:skip + limit]
Right — one dependency, reused with Depends
def common_params(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}

@app.get("/items")
def list_items(params: dict = Depends(common_params)):
    return ITEMS[params["skip"]:]

Raising the default limit now takes one edit, in common_params, not one per route.

2 — Reuse One Dependency Across Several Routes

A dependency is just a function, so nothing stops two different routes from calling the same one. You add Depends(common_params) to a second route's parameters, and it runs the exact same code there too.

FastAPI calls the dependency fresh for each request, but the function body never changes between routes. One fix, written once, reaches every route that uses it.

The same common_params paging logic serves two different record types.

3 — Give a Dependency a Parameter, and Chain One Onto Another

Sometimes a dependency itself needs a setting, decided before any request arrives. A dependency factory is a function that takes that setting and returns the real dependency. You call the factory once, then hand its result to Depends().

A dependency can also use another dependency. FastAPI resolves this sub-dependency first. It then passes the result into the one that needs it, just like a route uses Depends().

valid_choice(allowed) — a dependency that remembers a setting

The inner function keeps using allowed long after valid_choice returns.

You type 
def valid_choice(allowed: list[str]):
    def check(value: str):
        if value not in allowed:
            raise ValueError(f"{value} not in {allowed}")
        return value
    return check

check_color = valid_choice(["red", "green", "blue"])
print(check_color("green"))
Python shows 
green
  1. def valid_choice(allowed: list[str]): takes the setting once, before any request.
  2. def check(value: str): is the real dependency, called for every request.
  3. check_color = valid_choice(["red", "green", "blue"]) builds one specific, ready-to-use dependency.

4 — Set Up and Clean Up With yield

A dependency written with return only ever runs setup. Writing it with yield instead lets it pause, then run cleanup after the route uses its value. FastAPI resumes the function once the route finishes.

Put the cleanup in a finally block, and it still runs even when the route raises an error. Nothing you set up gets left behind.

yield "ready" — one function, two stops

next() runs the function up to its yield, then again past it.

You type 
def step():
    print("setup")
    yield "ready"
    print("cleanup")

gen = step()
value = next(gen)
print(value)
next(gen, None)
Python shows 
setup
ready
cleanup
  1. def step(): is a generator function, because it contains yield.
  2. yield "ready" pauses here and hands back "ready".
  3. next(gen, None) resumes after the yield, the step FastAPI takes for you.

🌟 Case Study: Counting Requests Still Being Handled

Future Vision wants to know how many requests are in flight at once, without touching a database yet.

before track_request runs0

+1 at setup, −1 at cleanup: the count always lands back at 0 ✓

ACTIVE["count"] += 1, then try / finally — setup and cleanup around the route

The dependency below stands in for anything that must be released after the route runs.

You type 
ACTIVE = {"count": 0}

def track_request():
    ACTIVE["count"] += 1
    try:
        yield ACTIVE["count"]
    finally:
        ACTIVE["count"] -= 1

def enquiry_status(request_number):
    return {"request_number": request_number, "in_flight": ACTIVE["count"]}

gen = track_request()
value = next(gen)
result = enquiry_status(value)
next(gen, None)
print(result)
print(ACTIVE["count"])
Python shows 
{'request_number': 1, 'in_flight': 1}
0
  1. ACTIVE["count"] += 1 runs before the route, as setup.
  2. yield ACTIVE["count"] hands the route its number and pauses here.
  3. finally: keeps the next line running even if the route fails.
  4. next(gen, None) resumes the generator, running the cleanup line.
Warning — skip try/finally and cleanup can be lost

Without try, an error in the route stops the function before ACTIVE["count"] -= 1 ever runs.

A failing route, with the same cleanup — change the route, not the dependency

This time the route raises an error, and the count still returns to 0.

5 — A Class as a Dependency, Applied to a Whole App

A function dependency forgets everything once it returns. A class-based dependency is a class with a __call__ method, so one instance can carry a setting between calls.

FastAPI calls that instance like a function, with the setting already fixed in __init__.

def __call__(self, value): — an instance that acts like a function

factor is fixed once, then used on every call.

You type 
class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def __call__(self, value):
        return value * self.factor

double = Multiplier(2)
print(double(5))
Python shows 
10
  1. def __init__(self, factor): runs once, when you build the instance.
  2. def __call__(self, value): runs every time FastAPI calls that instance.
  3. double = Multiplier(2) fixes factor at 2, before any call happens.

🌟 Case Study: One Shared Key for the Admin Routes

Future Vision's small admin team shares one key, sent as a header.

You will build real sign-in in a later lesson. This check only compares one header to one stored key.

x_api_key: str = Header(None) — the class reads the key from the request

A wrong key fails; the real key passes.

You type 
from fastapi import Header, HTTPException

class RequireKey:
    def __init__(self, key):
        self.key = key

    def __call__(self, x_api_key: str = Header(None)):
        if x_api_key != self.key:
            raise HTTPException(status_code=401, detail="Wrong key")
        return x_api_key

require_key = RequireKey("fvc-admin-2026")

try:
    require_key(x_api_key="guess")
except HTTPException as exc:
    print(exc.status_code)
