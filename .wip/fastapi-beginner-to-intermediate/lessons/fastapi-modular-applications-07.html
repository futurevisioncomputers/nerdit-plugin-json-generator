1 — 🔍 Why Split an Application Into Files

One file keeps growing every time you add a route, until scrolling past yesterday's code takes longer than writing today's. A module is one Python file. Splitting a big app into several modules keeps each one focused on one job. It is like one spreadsheet tab per topic, instead of one giant tab.

Python groups related modules into a package: a folder that holds an __init__.py file. That file can stay completely empty. Its only job is to mark the folder as one importable unit. Without it, Python treats the folder as a pile of loose scripts, not a package.

Reach for a package once a project has more than two or three groups of routes. A single small app with five routes rarely needs one yet.

main.py sits beside the routers package; __init__.py marks that folder as one unit Python can import.

Create this layout once, before writing any router. The folder name can be anything; routers is the name this lesson, and most FastAPI projects, use.

$ mkdir fastapi-modular-app $ cd fastapi-modular-app $ mkdir routers $ type nothing > routers/__init__.py # macOS/Linux: touch routers/__init__.py
Tip: An empty __init__.py is normal. Add code to it only when a package needs to run setup the moment it is imported.

2 — ➕ Create the Enquiries Router

Every route still needs a place to live once it moves out of main.py. An APIRouter is a small object that collects a related group of routes. It works like FastAPI() does, but meant to sit in its own file. You decorate functions on it with @router.get(), exactly as you decorated app in earlier lessons.

A router does nothing on its own until something else plugs it into the real app. Until then, it only remembers which function answers which path, in a plain list called router.routes.

🌟 Case Study: Giving Enquiries Their Own Router

Future Vision's enquiry list, the same rows from Lesson 1, is moving out of main.py into its own file, routers/enquiries.py.

APIRouter() — collect routes before main.py even exists

This file builds its own router, with no app in sight. FastAPI only needs the object later, in Lesson section 4.

You type 
from fastapi import APIRouter

enquiries_router = APIRouter()
ENQUIRIES = [
    {"enquiry_id": "E1", "branch": "Citylight", "course": "Python Professional", "follow_ups": 1},
    {"enquiry_id": "E3", "branch": "Pal", "course": "Business Analytics", "follow_ups": 1},
]

@enquiries_router.get("/")
def list_enquiries():
    return ENQUIRIES

@enquiries_router.get("/{enquiry_id}")
def get_enquiry(enquiry_id: str):
    for row in ENQUIRIES:
        if row["enquiry_id"] == enquiry_id:
            return row
    return {"error": "not found"}

print([route.path for route in enquiries_router.routes])

  3. for row in ENQUIRIES: scans the list the same way Lesson 1's route did.
  4. print([route.path for route in enquiries_router.routes]) lists the router's own paths, with no prefix yet.

class Router:
    def __init__(self):
        self.routes = []
    def get(self, path):
        def wrap(fn):
            self.routes.append(path)
            return fn
        return wrap

router = Router()

@router.get("/")
def list_all():
    return []

@router.get("/{item_id}")
def get_one(item_id):
    return {}

print(router.routes)

3 — ➕ Create the Learners Router

A second router can carry a completely different kind of setup from the first. Nothing stops one router from reading an in-memory list while another talks to a real database. Each file only has to answer its own group of routes.

Keeping that setup inside the router's own file means routers/learners.py can change its database code without anyone touching routers/enquiries.py. The two files never need to know about each other.

You type 
from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy import create_engine, String, Integer, Float
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, sessionmaker

engine = create_engine("sqlite:///./learners.db")

class Base(DeclarativeBase):
    pass

class Learner(Base):
    __tablename__ = "learners"
    learner_id: Mapped[str] = mapped_column(String, primary_key=True)
    branch: Mapped[str] = mapped_column(String)
    age: Mapped[int] = mapped_column(Integer)
    weekly_study_hours: Mapped[float] = mapped_column(Float)

Base.metadata.create_all(engine)
SessionLocal = sessionmaker(bind=engine)

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

learners_router = APIRouter()

@learners_router.get("/{learner_id}")
def get_learner(learner_id: str, db=Depends(get_db)):
    learner = db.get(Learner, learner_id)
    if learner is None:
        raise HTTPException(status_code=404, detail="Learner not found")
    return learner.branch

print([route.path for route in learners_router.routes])

4 — 🔗 Connect the Routers in main.py

How do two separate router files become one working API? app.include_router() is that join: it takes a prefix, text FastAPI glues onto the front of every route in that router.

app.include_router() takes a router object and copies its routes onto the real app. It works as if you had written those routes there yourself. Tags group those same routes under one heading in the interactive docs. A growing API then reads like a short list of sections, not one long list.

app.include_router(prefix=, tags=) — turn two routers into one API

Both routers from sections 2 and 3 plug into the same app here, each with its own prefix.

You type 
from fastapi import FastAPI

app = FastAPI()
app.include_router(enquiries_router, prefix="/enquiries", tags=["enquiries"])
app.include_router(learners_router, prefix="/learners", tags=["learners"])

paths = [prefix + route.path for prefix, rtr in [("/enquiries", enquiries_router), ("/learners", learners_router)] for route in rtr.routes]
print(paths)
Python shows 
['/enquiries/', '/enquiries/{enquiry_id}', '/learners/{learner_id}']
  1. app.include_router(enquiries_router, prefix="/enquiries", tags=["enquiries"]) copies section 2's routes onto app, prefixed.
  2. app.include_router(learners_router, prefix="/learners", tags=["learners"]) does the same for section 3's router.
  3. paths = [prefix + route.path for prefix, rtr in [("/enquiries", enquiries_router), ("/learners", learners_router)] for route in rtr.routes] joins each prefix onto its router's own paths by hand.
  4. print(paths) shows every path with its prefix already joined on.

5 — 🔍 Run the Modular Project and Trace a Request

Running a multi-file project is almost the same as running one file, with one extra rule. You still start Uvicorn and point it at the app object. Run the command from the folder that holds main.py, never from inside routers/.

Python looks for the routers package from the folder you ran the command in. From the wrong folder, that import fails, and the server never starts.

    return {tag: len(routes) for tag, routes in routers.items()}
