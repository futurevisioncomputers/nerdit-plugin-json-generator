🚀 Getting Started with FastAPI

📘 Lesson Overview: How do you turn an empty folder into a working web API in a few minutes? You will set up a Python project, install fastapi and uvicorn, and run your first route.

1 — Create the Project Folder and a Virtual Environment

Where should the files for a new web API live? A project folder is one folder that holds every file for this app, kept apart from your other code.

Every Python project can need its own package versions. A virtual environment is a private copy of Python just for one folder, so two projects never clash.

Create the folder first, then the environment inside it.

mkdir & cd — make the project folder

These two commands make a new folder and step inside it, so every later command runs from the right place.

$ mkdir fastapi-getting-started $ cd fastapi-getting-started # your terminal prompt now shows the new folder

python -m venv venv — make and turn on the virtual environment

The command that creates a virtual environment is the same on every system. The command that activates it is not, so Windows and macOS/Linux get their own tab.

python -m venv venv
venv\Scripts\activate
python3 -m venv venv
source venv/bin/activate
Terminal shows
(venv) $
  1. python -m venv venv creates a folder named venv holding a private copy of Python.
  2. venv\Scripts\activate (or source venv/bin/activate) turns that copy on for this terminal.
Command → what it doesmkdir fastapi-getting-started → creates the project folder
cd fastapi-getting-started    → moves your terminal into it
python -m venv venv           → creates the virtual environment

Make a new virtual environment for every project, so its packages never mix with another project's.

Tip: Run the activate command again any time you open a new terminal window for this project.

2 — Install FastAPI and Write Your First App

How do you add FastAPI's code to your project? pip is Python's package installer. It downloads a library and every package that library needs.

A FastAPI app is the one object that collects every address, or route, your API will answer. You create the app once, then attach routes to it with a decorator.

pip install fastapi uvicorn — with your venv active, add both libraries

$ pip install fastapi uvicorn Successfully installed fastapi-0.115.6 starlette-0.41.3 pydantic-2.10.3 click-8.1.7 uvicorn-0.32.1 # pip also installs the smaller packages fastapi and uvicorn depend on

@app.get("/") — connect one URL to one function

Save this as main.py. The @app.get("/") decorator tells FastAPI which function answers a request for the path /.

You type 
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}


print(read_root())
Python shows 
{'message': 'Hello, FastAPI!'}
  1. from fastapi import FastAPI brings in the class every route needs.
  2. app = FastAPI() creates the app that will collect your routes.
  3. @app.get("/") registers read_root for GET requests to /.
  4. return {"message": "Hello, FastAPI!"} sends back a plain Python dict as JSON.

Reach for a new route whenever your API needs to answer a new URL; one function handles one path.

3 — Run the App and Open the Automatic Docs

How do you turn main.py into a running web server? Uvicorn is the server that loads your FastAPI app and listens for requests.

FastAPI also reads your routes and writes automatic docs: an interactive page at /docs, with no extra work from you.

🌟 Case Study: Running the Admissions API

Future Vision's admissions team can now start the exact file you built in section 2.

uvicorn main:app --reload — start the server and watch for changes

Activate your venv from section 1, then run this from the same folder as main.py.

$ uvicorn main:app --reload INFO: Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit) INFO: Started reloader process using WatchFiles INFO: Application startup complete. # Press Ctrl+C to stop the server

Open http://127.0.0.1:8000 in your browser. The page shows the JSON your route returns: {"message": "Future Vision Admissions API is running"}.

main:app tells Uvicorn to look inside main.py for the app object. --reload restarts the server the moment you save a change.

/docs — try a route without writing a request

Open http://127.0.0.1:8000/docs to see every route listed, built straight from your code.

It lists GET /, with a Try it out button that opens a form and an Execute button that sends the real request. The response body comes back as {"message": "Future Vision Admissions API is running"}, the same JSON your browser showed at the plain URL.

Tip: Add .env to .gitignore (section 5) so secrets never reach Git history.

4 — Save Dependencies and Configuration

A teammate needs your exact package list, and your app needs settings that differ by computer. A requirements file lists every installed package; an .env file holds settings outside your code.

pip freeze prints every installed package, pinned by ==. Redirecting it into requirements.txt lets a teammate run pip install -r requirements.txt to match your versions exactly.

pip freeze > requirements.txt — write down what you installed

$ pip freeze > requirements.txt $ cat requirements.txt fastapi==0.115.6 python-dotenv==1.0.1 uvicorn==0.32.1 # pip freeze also lists the smaller packages these depend on

.env — one setting per line, outside your code

You type 
APP_NAME=FastAPI Getting Started
python-dotenv reads

One setting, APP_NAME, ready for os.getenv to read.

python-dotenv's load_dotenv() reads a file like this one and lets os.getenv read its values anywhere in your code.

load_dotenv() — read main.py's setting from .env

Add these lines to main.py from section 2, then read APP_NAME instead of writing it in the file.

You type 
import os

from dotenv import load_dotenv
from fastapi import FastAPI

load_dotenv()
app = FastAPI()


@app.get("/")
def read_root():
    return {"message": os.getenv("APP_NAME")}
Python shows

With .env beside main.py, calling read_root() now returns the value load_dotenv() loaded, not a message typed into the file.

  1. load_dotenv() finds .env next to main.py and loads its lines.
  2. APP_NAME=FastAPI Getting Started in .env sets one setting, with no quotes needed.
  3. return {"message": os.getenv("APP_NAME")} reads that setting back inside your route.
File → what it holdsrequirements.txt → the exact packages pip install needs
.env              → settings and secrets your code reads at startup
Warning — never commit .env

A real .env can hold passwords or API keys. Section 5 keeps it out of Git entirely.

5 — Protect Local Files and Run the App Directly

Which files should never reach a shared repository? Your .gitignore file lists folders and files Git should always skip, like venv and .env.

How do you run a script directly instead of through Uvicorn's command? The __main__ guard checks whether Python ran this file itself, not just imported it.

.gitignore — keep local files out of Git

Create this file once, before your first commit.

You type 
venv/
.env
__pycache__/
*.pyc
Git shows 
On branch main
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .gitignore
        main.py
        requirements.txt
  1. venv/ skips your whole virtual environment; a teammate rebuilds their own from requirements.txt.
  2. .env keeps your settings and secrets out of Git entirely.
  3. __pycache__/ and *.pyc skip Python's own compiled files.

None of those four kinds of files appear in the untracked list above.

if __name__ == "__main__": — an alternative to the uvicorn command

Every module has a __name__. Running a file directly sets it to "__main__"; importing that file sets it to the file's own name instead.

You type 
import uvicorn
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}


if __name__ == "__main__":
    uvicorn.run("main:app", host="127.0.0.1", port=8000, reload=True)
Python shows 
{'message': 'Hello, FastAPI!'}
main
  1. import uvicorn imports the library this file now runs directly.
  2. from fastapi import FastAPI is the same import as section 2.
  3. app = FastAPI() is the same pattern as section 2.
  4. @app.get("/") registers the route, as in section 2.
  5. def read_root(): is the function that answers /.
  6. return {"message": "Hello, FastAPI!"} is the JSON FastAPI sends back.
  7. if __name__ == "__main__": is true only when you run this file directly.
  8. uvicorn.run("main:app", host="127.0.0.1", port=8000, reload=True) starts the server, the same way the terminal command in section 3 does.

Save the file, activate your venv from section 1, and run it directly:

$ python main.py INFO: Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit) # Press Ctrl+C to stop the server

Loading main.py as a module printed main for __name__, so the guard's server never started. Run it directly and __name__ becomes "__main__" instead, so it does.

Tip: Most teams still start their server with uvicorn main:app --reload; the __main__ guard is handy for scripts that must run the same way everywhere.
