1 — Create a Route for Every HTTP Method

How does FastAPI know that a GET and a POST sent to the same address mean two different things? Each request carries one HTTP method, a verb that says what action the client wants.

You already used @app.get for one address in Lesson 1. FastAPI has a matching decorator for the other common verbs too, so one path can mean five different actions.

HTTP method → what it usually meansGET    → read data, never change it
POST   → create something new
PUT    → replace something completely
PATCH  → change part of something
DELETE → remove something

@app.get and @app.post — read a list, then add to it

Both routes answer the same path, /tasks; the method sent decides which function runs.

You type 
from fastapi import FastAPI

app = FastAPI()
TASKS = ["water the plants", "revise notes"]


@app.get("/tasks")
def list_tasks():
    return TASKS


@app.post("/tasks")
def add_task():
    TASKS.append("submit the report")
    return TASKS


print(list_tasks())
print(add_task())
Python shows 
['water the plants', 'revise notes']
['water the plants', 'revise notes', 'submit the report']
  1. @app.get("/tasks") registers list_tasks for GET requests to /tasks.
  2. @app.post("/tasks") registers a different function for POST on that same path.
  3. TASKS.append("submit the report") is the new row POST adds; GET never changes the list.

@app.put, @app.patch and @app.delete — replace, change part, or remove

The three remaining verbs act on the same list, each in its own way.

You type 
@app.put("/tasks")
def replace_tasks():
    TASKS[:] = ["start fresh"]
    return TASKS


@app.patch("/tasks")
def rename_first_task():
    TASKS[0] = "water the plants today"
    return TASKS


@app.delete("/tasks")
def clear_tasks():
    TASKS.clear()
    return TASKS


print(replace_tasks())
print(rename_first_task())
print(clear_tasks())
Python shows 
['start fresh']
['water the plants today']
[]
  1. TASKS[:] = ["start fresh"] throws away the old list and puts one new row in its place — a full PUT replace.
  2. TASKS[0] = "water the plants today" changes only the first row, leaving the rest untouched — a PATCH.
  3. TASKS.clear() empties the list completely, which is what DELETE does to the row it targets.

Reach for GET and DELETE when nothing you send needs checking. Reach for POST, PUT or PATCH whenever the request changes stored data.

Tip: Open /docs after running your app; it lists every method on every path, each in its own colour.

2 — Path Parameters: One Value or Many

How do you point one route at thousands of different records without writing thousands of functions? A path parameter is a named slot inside the URL itself, written in curly braces.

FastAPI reads the text between the slashes. It passes that text to your function as a plain argument, matched by name. You can also add more than one slot to the same path.

GET /items/{item_id} — one slot in the path

The part after /items/ becomes item_id inside the function.

You type 
from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
def read_item(item_id: str):
    return {"item_id": item_id}


print(read_item("42"))
Python shows 
{'item_id': '42'}
  1. @app.get("/items/{item_id}") marks item_id as a value the URL supplies, not a fixed word.
  2. def read_item(item_id: str): takes that value as a normal parameter, typed as text.

Use a path parameter whenever the value picks out one specific record, like an id in the address itself.

3 — Query Parameters, Defaults and Combining Them with a Path

How do you let a client narrow a list without changing the path itself? A query parameter is a name and value added after a ? in the URL, like ?keyword=pen.

FastAPI reads any simple parameter not written in the path as a query parameter. Give it a default value and it becomes optional, with a safe fallback when it's missing.

keyword and max_results — a required value, then one with a default

A plain parameter is required; adding a default makes it optional and falls back to that value.

You type 
@app.get("/search")
def search_items(keyword: str | None = None, max_results: int = 10):
    return {"keyword": keyword, "max_results": max_results}


print(search_items())
print(search_items(keyword="pen", max_results=5))
Python shows 
{'keyword': None, 'max_results': 10}
{'keyword': 'pen', 'max_results': 5}
  1. def search_items(keyword: str | None = None, max_results: int = 10): gives both parameters a default, so neither is required.
  2. print(search_items()) with no arguments shows both fallback values at once.

Add a default whenever a sensible value exists. Leave a query parameter required only when the request means nothing without it.

4 — Validate Parameters, Headers and Cookies

How do you stop a client from sending a value that's too short, too long or out of range? Validation checks a value against a rule before your function runs. Path() and Query() add these rules in place of a plain default. Each can set a minimum length, a maximum, or a number range.

A request also carries headers: extra labelled values sent with it. It also carries cookies: small values the browser stored and resends on its own. Header() and Cookie() read them the same way Query() reads the query string.

Where a value comes fromPath parameter  → part of the URL path itself
Query parameter → after the ? in the URL
Header          → Header() reads a named request header
Cookie          → Cookie() reads a value the browser already stored

Query(min_length=2) — a rule on a query parameter

Calling the function directly still works with a valid value, since this is plain Python underneath.

You type 
from fastapi import Query

app = FastAPI()


@app.get("/search")
def search_products(keyword: str = Query(min_length=2, max_length=20)):
    return {"keyword": keyword}


print(search_products(keyword="pen"))
Python shows 
{'keyword': 'pen'}
  1. def search_products(keyword: str = Query(min_length=2, max_length=20)): replaces a plain default with a rule.

Calling a route function directly, as above, skips the rule completely. Only a real request goes through FastAPI's check. Send ?keyword=p to a running server, and FastAPI answers with a 422 error before search_products ever runs.

🌟 Case Study: A Validated Lookup That Also Reads Who's Asking

Future Vision wants every enquiry_id checked for a sensible length, and wants to know which counsellor is asking.

Path(), Header() and Cookie() together — one route, every kind of value

This program runs for real, so its output comes from an actual request, not a direct call.

You type 
from fastapi import Cookie, FastAPI, Header, Path, Query

app = FastAPI()

ENQUIRIES = [
    {"enquiry_id": "E1", "branch": "Citylight", "course": "Python Professional", "follow_ups": 1},
    {"enquiry_id": "E2", "branch": "Citylight", "course": "Office & GenAI", "follow_ups": 3},
    {"enquiry_id": "E3", "branch": "Pal", "course": "Business Analytics", "follow_ups": 1},
    {"enquiry_id": "E5", "branch": "Vesu", "course": "Excel & Power BI", "follow_ups": 1},
    {"enquiry_id": "E6", "branch": "Pal", "course": "Python Professional", "follow_ups": 1},
    {"enquiry_id": "E7", "branch": "Vesu", "course": "Business Analytics", "follow_ups": 4},
]


@app.get("/enquiries/{enquiry_id}")
def get_enquiry(
    enquiry_id: str = Path(min_length=2, max_length=4),
    verbose: bool = Query(default=False),
    x_counsellor: str | None = Header(default=None),
    session_id: str | None = Cookie(default=None),
):
    row = next((r for r in ENQUIRIES if r["enquiry_id"] == enquiry_id), None)
    if not verbose:
        return {"enquiry_id": enquiry_id, "found": row is not None}
    return {"row": row, "counsellor": x_counsellor, "session": session_id}


if __name__ == "__main__":

    uvicorn.run(app, host="127.0.0.1", port=8000)

5 — Why Doesn't My Route Answer? Enum Choices and Route Order

What stops a client from sending branch=Delhi when the institute has only three branches? An Enum lists the only values FastAPI should accept.

Use str, Enum together. Each member becomes a plain string FastAPI can read from the URL and check against its list.

class Size(str, Enum) — only three sizes are valid

Calling the route with a real member works normally, the same as any other direct call.

You type 
from enum import Enum


class Size(str, Enum):
    small = "S"
    medium = "M"
    large = "L"


@app.get("/shirts/{size}")
def shirt_price(size: Size):
    prices = {Size.small: 399, Size.medium: 449, Size.large: 499}
    return {"size": size.value, "price": prices[size]}


print(shirt_price(Size.medium))
Python shows 
{'size': 'M', 'price': 449}
  1. class Size(str, Enum): lists the three valid sizes.
  2. def shirt_price(size: Size): makes FastAPI check the value against that list.

Send /shirts/XL to a real server and FastAPI rejects it with a 422 error. It lists S, M and L as the choices.

A second surprise is how FastAPI picks a route. It checks every registered path in order, and the first match wins.

which_rule(value) — the first matching rule always wins

A broad rule registered first can catch a value meant for a later, more exact rule.

You type 
rules = [
    ("starts with A", lambda s: s.startswith("A")),
    ("is exactly 'Admin'", lambda s: s == "Admin"),
]


def which_rule(value):
    for name, check in rules:
        if check(value):
            return name
    return "no match"


print(which_rule("Admin"))
Python shows 
starts with A
  1. for name, check in rules: walks the list in the order it was written.
  2. return name stops at the first match, even though a later rule is more exact.

🌟 Case Study: Restricting Future Vision's Branches and Fixing a Route Order Bug

A fixed path, like /enquiries/stats, is a route too, checked by the same first-match rule.

Wrong order — the parameter route goes first
@app.get("/enquiries/{enquiry_id}")
def get_enquiry(enquiry_id: str):
    ...

@app.get("/enquiries/stats")
def enquiry_stats():
    return {"total": len(ENQUIRIES)}
Fixed — the exact path goes first
@app.get("/enquiries/stats")
def enquiry_stats():
    return {"total": len(ENQUIRIES)}

@app.get("/enquiries/{enquiry_id}")
def get_enquiry(enquiry_id: str):
    ...

In the wrong order, /enquiries/stats matches {enquiry_id} first, so enquiry_id becomes "stats". The real route never runs; the fix is registering the fixed path first.

The fixed route order, with the branch Enum — the whole file, checked for real

This file puts /enquiries/stats first, and restricts branch to the three real branches.
