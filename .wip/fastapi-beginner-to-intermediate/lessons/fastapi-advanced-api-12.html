1 — Paging, Filtering and Sorting a List

How do you send back a slice of a long list instead of all of it at once? Pagination limits each reply to one small page of rows.

Two query parameters work together. skip says how many rows to leave out, and limit says how many to return after that.

page(items, skip, limit) — slice first, send only a page

A plain Python list shows the idea first: skip past rows, then keep a limited number.

You type 
names = ["Aarav", "Diya", "Kabir", "Meera", "Riya", "Vihan", "Zara", "Om"]

def page(items, skip=0, limit=3):
    return items[skip: skip + limit]

print(page(names, skip=0, limit=3))
print(page(names, skip=3, limit=3))
Python shows 
['Aarav', 'Diya', 'Kabir']
['Meera', 'Riya', 'Vihan']
  1. names = ["Aarav", "Diya", "Kabir", "Meera", "Riya", "Vihan", "Zara", "Om"] is the full list, eight names long.
  2. def page(items, skip=0, limit=3): takes the list plus how many rows to skip and keep.
  3. return items[skip: skip + limit] slices out just that page.

Use paging whenever a list can grow past a screen's worth of rows.

branch & sort — keep only what matches, in the order you choose

branch keeps only one branch; sort orders the result.

You type 
@app.get("/enquiries")
def list_enquiries(skip: int = 0, limit: int = 10, branch: str | None = None, sort: str | None = None):
    rows = ENQUIRIES
    if branch:
        rows = [r for r in rows if r["branch"] == branch]
    if sort:
        key = sort.lstrip("-")
        rows = sorted(rows, key=lambda r: r[key], reverse=sort.startswith("-"))
    return rows[skip: skip + limit]
FastAPI shows

branch=Vesu and sort=-age return Vesu's rows, oldest first: E7, then E5.

  1. def list_enquiries(skip: int = 0, limit: int = 10, branch: str | None = None, sort: str | None = None): adds branch and sort as optional parameters.
  2. rows = [r for r in rows if r["branch"] == branch] keeps only rows from that branch.
  3. key = sort.lstrip("-") drops a leading - so -age still looks up age.
  4. rows = sorted(rows, key=lambda r: r[key], reverse=sort.startswith("-")) sorts ascending, or descending when sort starts with -.
Tip: Cap limit, for example at 100, so a client can't ask for the whole table at once.

2 — A Custom Exception Handler

What happens when ten different routes all need the same error shape for a missing record? An exception handler answers this once, for every route.

You write a plain Python exception class, then register a function for it with exception_handler. FastAPI calls that function whenever the exception is raised, anywhere in your code.

One question decides the shape of the answer: a missing id always gets the same 404 error.

Reach for this instead of repeating HTTPException in every route that can hit the same error.

🌟 Case Study: A Clear Error When an Enquiry Is Missing

Neha's team often looks up one enquiry by its id, and the id can be wrong.

@app.exception_handler — one answer for every missing enquiry

A custom exception class carries the missing id; the handler turns it into one JSON shape.

You type 
from fastapi import Request
from fastapi.responses import JSONResponse


class EnquiryNotFoundError(Exception):
    def __init__(self, enquiry_id: str):
        self.enquiry_id = enquiry_id


@app.exception_handler(EnquiryNotFoundError)
async def enquiry_not_found_handler(request: Request, exc: EnquiryNotFoundError):
    return JSONResponse(
        status_code=404,
        content={"error": "enquiry_not_found", "enquiry_id": exc.enquiry_id},
    )


@app.get("/enquiries/{enquiry_id}")
def get_enquiry(enquiry_id: str):
    for row in ENQUIRIES:
        if row["enquiry_id"] == enquiry_id:
            return row
    raise EnquiryNotFoundError(enquiry_id)
FastAPI shows

Visiting /enquiries/E99, an id that doesn't exist, returns status 404 with {'error': 'enquiry_not_found', 'enquiry_id': 'E99'}. FastAPI would otherwise send a plain 500 error.

  1. class EnquiryNotFoundError(Exception): defines a plain error for one missing id.
  2. @app.exception_handler(EnquiryNotFoundError) registers the function below for that error, on the same app from section 1.
  3. content={"error": "enquiry_not_found", "enquiry_id": exc.enquiry_id}, builds the one shared error shape.
  4. raise EnquiryNotFoundError(enquiry_id) is the only thing a route has to do.
Tip: Register one handler per exception type; FastAPI picks the most specific match when you raise it.

3 — Lifespan Events: Startup and Shutdown

What runs once when your server starts, and once when it stops? A lifespan function wraps your whole app in one place for both.

You write it with asynccontextmanager: the code before yield runs at startup, and the code after it runs at shutdown. FastAPI runs this once, not per request.

You used asyncio.gather for several tasks together in lesson 11. A lifespan function is a different async pattern that wraps your whole app.

Use it for things like opening a database connection once, not per request.

The code before yield runs once at startup; the code after it runs once at shutdown.

🌟 Case Study: Opening and Closing the Enquiry Desk

Future Vision's API should log one line when the enquiry desk opens, and one when it closes.

asynccontextmanager — one open, one close, around every request

Entering this context prints the startup line; leaving it prints the shutdown line.

You type 
import asyncio
from contextlib import asynccontextmanager
from fastapi import FastAPI


@asynccontextmanager
async def lifespan(app: FastAPI):
    print("Startup: enquiry desk is open")
    yield
    print("Shutdown: enquiry desk is closed")


app = FastAPI(lifespan=lifespan)


async def demo():
    async with lifespan(app):
        print("Serving requests...")


asyncio.run(demo())
Python shows 
Startup: enquiry desk is open
Serving requests...
Shutdown: enquiry desk is closed
  1. async def lifespan(app: FastAPI): opens the function asynccontextmanager wraps.
  2. print("Startup: enquiry desk is open") runs once, before the yield.
  3. yield pauses here while the app serves requests.
  4. print("Shutdown: enquiry desk is closed") runs once, after the yield.

Leave out yield and Python raises RuntimeError: a lifespan function must pause exactly once.

4 — Real-Time Updates: WebSockets and Server-Sent Events

How does a server push new data to a browser on its own? A WebSocket opens one connection both sides keep using.

You accept the connection, then call receive_text and send_text as many times as you like, either way.

Use it when both sides must speak, like a live chat between a counsellor and a learner.

Server-Sent Events, or SSE, push updates only one way: server to client, over plain HTTP.

A browser reconnects on its own if the response ends.

Same three questions asked of both — the answer to "direction" is the whole difference.

Choose SSE for one-way feeds; choose a WebSocket when the client must reply too.

🌟 Case Study: Neha's Live Enquiry Channel

Neha's admissions chat widget needs two-way messages; the branch dashboard only needs one-way updates.

WebSocket — both sides keep the connection open

Accepting the connection lets the route read and write as many messages as it likes.

You type 
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()


@app.websocket("/ws/counsellor")
async def counsellor_chat(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            message = await websocket.receive_text()
            await websocket.send_text(f"Neha: got your message - {message}")
    except WebSocketDisconnect:
        pass
FastAPI shows

Sending "When does the Python batch start?" gets back "Neha: got your message - When does the Python batch start?"

  1. async def counsellor_chat(websocket: WebSocket): takes the connection as a WebSocket parameter.
  2. await websocket.accept() opens the connection before any messages move.
  3. message = await websocket.receive_text() waits for the next message from the browser.
  4. await websocket.send_text(f"Neha: got your message - {message}") replies on the same connection.

text/event-stream — push updates without opening a WebSocket

A generator yields one event at a time; StreamingResponse sends each one as it is ready.

You type 
from fastapi.responses import StreamingResponse


async def enquiry_updates():
    for minute in range(1, 4):
        yield f"data: {minute} new enquiry this minute\n\n"


@app.get("/stream/enquiries")
def stream_enquiries():
    return StreamingResponse(enquiry_updates(), media_type="text/event-stream")
FastAPI shows

Opening /stream/enquiries receives three events in a row: "data: 1 new enquiry this minute", then 2, then 3.

  1. async def enquiry_updates(): defines a generator that yields one event at a time.
  2. yield f"data: {minute} new enquiry this minute\n\n" sends one SSE-shaped line, blank line included.
  3. return StreamingResponse(enquiry_updates(), media_type="text/event-stream") streams those events as they are produced.
Tip: A real SSE feed keeps the generator open and sends new events as they happen; this example stops after three to keep the output short.

5 — Static Files and API Versioning

How does an API send back a file that never changes, like a PDF or an image? A static file doesn't need its own route; StaticFiles serves a whole folder as plain URLs.

Mount it once at a path such as /static, and every file there answers on its own.

How do you change an endpoint without breaking the app that already calls it? A version prefix like /v1 keeps the old shape live beside the new one.

Old clients keep calling the plain path; new clients call the versioned one.

🌟 Case Study: A Brochure File and a Versioned Course List

Future Vision wants a brochure download and a /v1/courses list that won't break the old website.

APIRouter(prefix="/v1") — the old shape and the new one, side by side

The legacy route keeps its wrapped shape; the v1 route returns the plain list.

You type 
from fastapi import APIRouter, FastAPI

app = FastAPI()

COURSES = ["Python Professional", "Business Analytics", "Office & GenAI"]


@app.get("/courses")
def list_courses_legacy():
    return {"courses": COURSES, "note": "old shape, kept for old clients"}


v1 = APIRouter(prefix="/v1")


@v1.get("/courses")
def list_courses_v1():
    return COURSES


app.include_router(v1)

print(list_courses_legacy())
print(list_courses_v1())

  2. def list_courses_legacy(): returns the list wrapped in a dict, the shape old clients expect.
  3. v1 = APIRouter(prefix="/v1") groups new routes under /v1, as in lesson 7.
  4. app.include_router(v1) connects them to the app, same as lesson 7's routers.
