1 — Choose a Status Code, and Send No Body With 204

Every response carries a status code, a short number that tells the client what happened. A 2xx code means success, a 4xx means the client erred, and a 5xx means the server failed. FastAPI replies with 200 by default, but a route can set a different one.

You set status_code=204 when a request succeeds with nothing to send back, like a delete. A 204 response has no body at all, not even an empty JSON object. Sending one tells the client the action worked, with no wasted bytes.

Situation → status codeCreated something new   → 201
Nothing to send back    → 204
Can't find the record   → 404
Data failed validation  → 422

A delete route often builds Response(status_code=204) directly, so you can see its empty body.

Response(status_code=204) — build the no-body reply yourself

You type 
from fastapi import Response

TASKS = [{"id": 1, "text": "water the plants"}, {"id": 2, "text": "revise notes"}]


def delete_task(task_id: int):
    TASKS[:] = [t for t in TASKS if t["id"] != task_id]


empty = Response(status_code=204)
print(empty.status_code)
print(empty.body)
Python shows 
204
b''
  1. def delete_task(task_id: int): removes the matching task from the list.
  2. empty = Response(status_code=204) builds the same reply FastAPI sends for a 204 route.
  3. print(empty.body) shows the body is empty, not just short.

2 — Shape the Response With response_model and response_model_exclude

A route can return more data than a client should see. A response model is a second Pydantic model that filters the return value before FastAPI sends it. Set it with response_model on the decorator, and only its fields reach the client.

response_model_exclude skips that second model. Hand the route a set of field names; FastAPI drops just those from the model you already have. It is a quick hide, with no new class.

response_model=UserOut — hide the password field

UserIn takes a password; UserOut, the response model, does not define one.

You type 
from pydantic import BaseModel


class UserIn(BaseModel):
    username: str
    password: str


class UserOut(BaseModel):
    username: str


new_user = UserIn(username="arjun99", password="hunter2")
print(UserOut.model_validate(new_user.model_dump()).model_dump())
Python shows 
{'username': 'arjun99'}
  1. class UserOut(BaseModel): keeps only the one field a client may see.
  2. print(UserOut.model_validate(new_user.model_dump()).model_dump()) drops password the same way response_model does.

🌟 Case Study: Hiding a Counsellor's Private Note

Neha adds a private note to some enquiries; the student-facing reply must never show it.

@app.get(..., response_model=EnquiryOut) — the decorator does the filtering

The route stays simple; EnquiryOut decides what leaves the server.

You type 
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

ENQUIRIES = [
    {"enquiry_id": "E1", "name": "Aarav Shah", "branch": "Citylight", "follow_ups": 1},
    {"enquiry_id": "E2", "name": "Priya Mehta", "branch": "Citylight", "follow_ups": 3},
]


class EnquiryOut(BaseModel):
    enquiry_id: str
    name: str
    branch: str
    follow_ups: int


@app.get("/enquiries/{enquiry_id}", response_model=EnquiryOut)
def get_enquiry(enquiry_id: str):
    for row in ENQUIRIES:
        if row["enquiry_id"] == enquiry_id:
            return row


full_row = {"enquiry_id": "E2", "name": "Priya Mehta", "branch": "Citylight",
            "follow_ups": 3, "internal_note": "asked about EMI"}
print(EnquiryOut.model_validate(full_row).model_dump())
Python shows 
{'enquiry_id': 'E2', 'name': 'Priya Mehta', 'branch': 'Citylight', 'follow_ups': 3}
  1. class EnquiryOut(BaseModel): is the model you set as response_model.
  2. @app.get("/enquiries/{enquiry_id}", response_model=EnquiryOut) tells FastAPI to filter every reply through it.
  3. print(EnquiryOut.model_validate(full_row).model_dump()) shows the private note already gone.

response_model_exclude={"internal_note"} — the same hide, no second model

EnquiryFull keeps the note; the exclude set drops it only for this route.

    for row in ENQUIRIES:
        if row["enquiry_id"] == enquiry_id:
            return row


print(EnquiryFull.model_validate(full_row).model_dump(exclude={"internal_note"}))

3 — Raise an Error With HTTPException and Build a JSONResponse

A lookup can fail: the id a client sent might not exist. Raising an HTTPException stops your function and sends a clear error status with a message. FastAPI turns it into JSON for you.

raise HTTPException(status_code=404) — a clear 404 instead of guessing

Catching it shows the exact status and message FastAPI would send back.

You type 
from fastapi import HTTPException

ITEMS = {1: "Pen", 2: "Notebook"}


def get_item(item_id: int):
    if item_id not in ITEMS:
        raise HTTPException(status_code=404, detail=f"Item {item_id} not found")
    return {"item_id": item_id, "name": ITEMS[item_id]}


try:
    get_item(9)
except HTTPException as exc:
    print(exc.status_code)
    print(exc.detail)
Python shows 
404
Item 9 not found
  1. raise HTTPException(status_code=404, detail=f"Item {item_id} not found") stops the function right there.
  2. except HTTPException as exc: catches it the same way FastAPI does for a real request.
  3. print(exc.status_code) shows the status the client would receive.
Wrong — a plain dict still looks like success
@app.get("/enquiries/{enquiry_id}")
def get_enquiry(enquiry_id: str):
    for row in ENQUIRIES:
        if row["enquiry_id"] == enquiry_id:
            return row
    return {"error": "not found"}
Right — raise HTTPException instead
@app.get("/enquiries/{enquiry_id}")
def get_enquiry(enquiry_id: str):
    for row in ENQUIRIES:
        if row["enquiry_id"] == enquiry_id:
            return row
    raise HTTPException(status_code=404, detail="Enquiry not found")

The wrong version still sends 200 OK, so a client's success check passes anyway.

Sometimes the status code depends on data you only know at run time. A JSONResponse is a response object you build yourself, with its own status code and body. Returning one gives you that control.

JSONResponse(status_code=202) — a different code when Citylight can't handle it

A branch other than Citylight gets a 202; Citylight gets a normal 200.

You type 
from fastapi.responses import JSONResponse


def escalate_enquiry(enquiry_id: str):
    row = next(r for r in ENQUIRIES if r["enquiry_id"] == enquiry_id)
    if row["branch"] != "Citylight":
        return JSONResponse(status_code=202, content={
            "status": "escalated_to_head_office", "enquiry_id": enquiry_id,
        })
    return {"status": "handled_at_branch", "enquiry_id": enquiry_id}


result = escalate_enquiry("E3")
print(result.status_code)
print(result.body.decode())
Python shows 
202
{"status":"escalated_to_head_office","enquiry_id":"E3"}
  1. if row["branch"] != "Citylight": decides the status code at run time, not at the decorator.
  2. return JSONResponse(status_code=202, content={ sends 202 with a shape of its own.
  3. print(result.body.decode()) shows the exact bytes FastAPI would send.

Reach for JSONResponse when the status code or shape changes with the data, not just with the route.

4 — Set Response Headers and Cookies

A route can add more to a reply than its body. A parameter typed Response gives you the real reply object before FastAPI sends it. You write to response.headers for a response header, or call response.set_cookie() to store a small cookie in the browser.

response.headers["X-..."] — add a header without changing the body

The body stays the same; only a new header rides along with it.

You type 
from fastapi import Response

VISITS = {"count": 0}


def home(response: Response):
    VISITS["count"] += 1
    response.headers["X-Visit-Count"] = str(VISITS["count"])
    return {"message": "Welcome"}


resp = Response()
print(home(resp))
print(resp.headers["x-visit-count"])
Python shows 
{'message': 'Welcome'}
1
  1. def home(response: Response): asks FastAPI for the real reply object.
  2. response.headers["X-Visit-Count"] = str(VISITS["count"]) rides along beside the body.
  3. print(resp.headers["x-visit-count"]) reads it back, in lower case.

response.set_cookie(key, value) — remember a value for next time

The same function now also asks the browser to keep a small value.

You type 
VISITS["count"] = 0


def home(response: Response):
    VISITS["count"] += 1
    response.headers["X-Visit-Count"] = str(VISITS["count"])
    response.set_cookie(key="theme", value="dark")
    return {"message": "Welcome"}


resp = Response()
print(home(resp))
print(resp.headers["x-visit-count"])
print(resp.headers["set-cookie"])
Python shows 
{'message': 'Welcome'}
1
theme=dark; Path=/; SameSite=lax
  1. response.set_cookie(key="theme", value="dark") asks the browser to keep this value.
  2. print(resp.headers["set-cookie"]) shows the exact cookie line sent with the reply.

Reach for a header or a cookie when the client needs a value that sits outside the body itself.

5 — Receive Simple Form Fields With Form()

Not every client sends JSON. An HTML <form> posts plain text fields instead, the way a paper form would. Form() reads one form field by name, the same way a query parameter reads one value from the URL.

Form() needs the python-multipart package, already in this course's requirements.txt. Without it, FastAPI raises an error the moment it starts.

name: str = Form(...) — one field per parameter

Calling the function directly, with plain keyword arguments, works the same way a real submit does.

You type 
from fastapi import Form


def contact_form(name: str = Form(...), message: str = Form(...)):
    return {"name": name, "message": message}


print(contact_form(name="Dev", message="When is the next batch?"))
Python shows 
{'name': 'Dev', 'message': 'When is the next batch?'}
  1. def contact_form(name: str = Form(...), message: str = Form(...)): tells FastAPI to read both fields from a form, not JSON.
  2. print(contact_form(name="Dev", message="When is the next batch?")) calls it directly, with plain text.

from fastapi import FastAPI, Form

def quick_enquiry(
